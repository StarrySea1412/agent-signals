一个文件，三种端点

把三条信号线装进同一份 FastAPI：/v1/weather、/ask/stream、/ws，一条命令起机房

现在兑现承诺：小晴的信号机房，整个后端就是一个 Python 文件。三种协议各占一个函数，REST 三个装饰器里最不起眼，却撑着另外两个的地基。

signal_room.pyFastAPI · 完整可跑 · uvicorn signal_room:app --reload
from fastapi import FastAPI, WebSocket
from fastapi.responses import StreamingResponse
import asyncio, json, httpx

app = FastAPI()

# ── 第一棒 · REST：工具调用的入口（第 2 章）──────────
@app.get("/v1/weather")
async def weather(city: str):
    async with httpx.AsyncClient() as client:
        r = await client.get(UPSTREAM, params={"city": city})
        if r.status_code == 429:                     # 礼貌：听 Retry-After 的
            await asyncio.sleep(int(r.headers.get("Retry-After", "5")))
            r = await client.get(UPSTREAM, params={"city": city})
        r.raise_for_status()
    data = r.json()
    return {"city": city, "temp": data["temp"], "wind": data["wind"]}

# ── 第二棒 · SSE：回答流出去（第 3 章）─────────────
@app.get("/ask/stream")
async def ask_stream(q: str):
    async def gen():
        async for chunk in llm_stream(q):            # 逐 token 生成
            yield f"data: {json.dumps({'delta': chunk}, ensure_ascii=False)}\n\n"
        yield "data: [DONE]\n\n"
    return StreamingResponse(gen(), media_type="text/event-stream")

# ── 第三棒 · WebSocket：能打断的语音对话（第 4 章）────
@app.websocket("/ws")
async def voice(sock: WebSocket):
    await sock.accept()                               # 101 握手在这里完成
    try:
        while True:
            msg = await sock.receive_text()           # 用户帧：说到一半也能来
            async for chunk in llm_stream(msg):
                await sock.send_text(chunk)           # 回答帧：边生成边发
    except Exception:
        pass                                          # 断线清理；重连是客户端的事

三个函数，三种性格

同一份代码里，三种协议的性格差一目了然：REST 端点最短，进去、拿数据、return，连接由框架收尾；SSE 端点是一个生成器——yield 一段就送一段，框架负责把每段标上 data: 和空行，media_type="text/event-stream" 就是那条传送带的出厂铭牌；WebSocket 端点是一个循环——accept() 之后连接一直活着，while True 里来一帧答一帧，是唯一需要你自己管生命周期的。

注意第 14 行那个 if r.status_code == 429：第 2 章说的「礼貌是协议的一部分」，落地就是这一行——读 Retry-After，睡够，再试。面试时聊到可靠性，能随手写出这三行的人不多。

JD 里「熟悉基本语法和常用库」的那张清单，其实就是这几个名字：

库在这份文件里干的活一句话记法

asyncioawait/async 的引擎：等请求时让出 CPU 去接别人一个服务员看十桌的能力

为什么满篇 async：对话服务的典型负载是「大量连接、各自等慢 IO」——等模型吐字、等上游 API。同步代码一个请求占一个线程，等着也是干等；异步代码等待时把服务员让出来服务别人。通信密集型服务的 Python，绕不开 async，这也是 JD 把「基本语法」和「通信方法」写在一句话里的深层原因。
